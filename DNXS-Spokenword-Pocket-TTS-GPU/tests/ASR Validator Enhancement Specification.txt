Target file: ASR/asr_validator.py

Supporting test data: Use the existing ASR failure logs and any chunk audio/text pairs already present in the repository. The previously generated standalone rewritten validator must not be treated as authoritative code.



Objective

Improve the ASR validator so it identifies genuine TTS audio defects while avoiding failures caused only by harmless ASR transcription differences.

The final audio is acceptable when it sounds like the supplied reference text when spoken, even when:

• punctuation differs

• capitalization differs

• spacing or hyphenation differs

• contractions are expanded

• numbers or ordinals are written differently • names or invented words are transcribed phonetically • deliberately phonetic homograph spellings are used, such as reed , red , lyve , or liv

The validator must still fail genuine defects such as:

• extra words or sentences

• missing words or clauses

• repeated words or phrases not present in the reference • truncated speech

• changed numbers

• changed negation

• unrelated speech

• foreign-language or nonsensical transcription • major spoken-content substitutions

Phase 1: Correct deterministic normalization defects

Fix the current normalization code before replacing scoring.

Roman numerals

The lowercase pronoun i must never be converted to 1 or one .

Roman-numeral conversion must be conservative. Do not interpret arbitrary lowercase prose words as Roman numerals.

Acceptable approaches include:

• only convert uppercase Roman numerals from the original text • require a multi-character Roman numeral • explicitly exclude standalone I

Add regression tests for:

Louis XIV



Ordinals and numbers

Normalize punctuation around numeric tokens before attempting ordinal conversion.

These must normalize equivalently:



20th

20th.

twentieth



Also support ordinary cardinal equivalents:



20

Contractions

Replace the limited hard-coded contraction list with a robust normalization method.

At minimum support:



I'm / I am

isn't / is not

wasn't / was not

weren't / were not

Support straight and curly apostrophes.

Avoid unsafe substring replacement. Perform token-aware or regex-boundary-aware expansion.

Punctuation and hyphenation

Treat punctuation, quotation marks, capitalization, and normal spacing differences as non-semantic.

For vocalized repeated syllables, hyphens must become token boundaries rather than disappearing.

Example:

The existing rapidfuzz.fuzz.ratio() character score must not be the primary correctness decision.

Implement token-level sequence alignment using dynamic programming.

The alignment must classify operations as:

• phonetic equivalent

• substitution

• insertion

• deletion

Phase 3: Spoken and phonetic equivalence

Do not map all possible pronunciations of a homograph to one canonical token.

The current style of mapping:



4





"read": ["reed", "red"]


can incorrectly make reed and red equivalent even though they sound different.

Instead:

1. Preserve the exact phonetic spelling supplied in the reference text. 2. Compare reference and hypothesis based on likely spoken sound. 3. Allow one reference token to align with multiple hypothesis tokens and the reverse.

Examples that may be equivalent:



Irongron

I wrong grown

Linx

links

Sontaran

son to run

Use a documented phonetic comparison method. Possible components include:

• phoneme conversion

• Double Metaphone

• pronunciation dictionaries

• constrained Soundex fallback

• character similarity only as a secondary signal

Do not use Soundex equality alone as sufficient proof of equivalence.

Add tests demonstrating that:



reed ≠ red

lyve ≠ liv

unless the ASR token itself is an ambiguous normal spelling whose pronunciation can validly correspond to the supplied phonetic reference.



Phase 4: Extra-speech detection

Explicitly detect unmatched speech before, inside, and after the matched reference.



5





Classify unmatched spans as:


• unexpected prefix

• unexpected internal speech

• unexpected suffix

Examples that must fail:



Reference: Why?

ASR: Why? Thank you.



Reference: Stop!

ASR: Stop. It is here.



Reference: Everything will be ready soon.

ASR: Everything will be ready soon. The car is dead too.



Do not permit a high general similarity score to hide an appended sentence.

Suggested failure rules:

• two or more consecutive unmatched content words • an unmatched clause

• an unmatched suffix longer than a small configurable tolerance • unmatched content exceeding a percentage of the reference length

Small ASR fillers may be classified as review rather than immediate failure, but this must be conservative and documented.



Phase 5: Missing-speech detection

Detect missing reference material through alignment rather than only word-count ratio.

Strongly penalize or automatically fail missing:

• negations

• numbers

• names

• content words

• complete clauses

• sentence endings

• two or more consecutive words



6





The existing < 40% word-count truncation rule may remain as an emergency detector, but it must not be the only missing-content detector.




Phase 6: Repetition and hallucination detection

Rewrite repetition detection using normalized spoken tokens from both reference and hypothesis.

Expected repetition in the reference must not be flagged.

Examples:



Reference: Linx! Linx, I say!

ASR: Links, links, I say.

This must not be classified as hallucination solely because links appears twice.



Reference: tra-lal-lal-lal-lal-la

ASR: la la la la la la

This must not be classified as severe hallucination solely because the ASR uses separate repeated tokens.

Unexpected examples such as these must fail:



gait gait gait gait gait gait gait

steaks steaks steaks steaks steaks

Implement correct repeated phrase detection for phrase lengths of at least two through six tokens.

For phrase length n , compare token blocks:



tokens[i:i+n] == tokens[i+n:i+(2*n)]

Do not advance by one token while testing repeated multiword blocks.

Calculate excess repetition relative to the reference:



unexpected count = hypothesis count - allowed reference count

Phase 7: Critical semantic tokens


Add special handling for tokens whose alteration changes meaning materially.

At minimum:

• negations: not , no , never , cannot • numbers and ordinals

• names and identifiers

• directional or polarity words where practical

A changed negation or number should normally fail even when the rest of the sentence matches.

Do not add a broad semantic model unless justified by tests and performance impact.



Phase 8: Classification and scoring

Return three classifications:



PASS

REVIEW

FAIL

REVIEW is for ASR uncertainty that is neither safely acceptable nor clearly defective.

Do not let minor_mismatch unconditionally override a low score.

A minor variation may pass only when all of these are true:

• no insertions

• no deletions

• no critical-token changes

• no unexpected repetition

• no material extra speech

• strong phonetic alignment

• high reference coverage

Suggested component scores:



reference coverage

phonetic agreement

extra-speech penalty

missing-speech penalty

substitution penalty



8





repetition penalty


critical-token integrity



Do not finalize numerical weights before regression tests exist.

Hard failure overrides should include:

• severe unexpected repetition

• material missing speech

• material extra speech

• changed negation

• changed number

• unrelated or foreign-language output

• extremely low reference coverage
